# pandora
Пандора это клиент-серверное приложение для хранения ваших секретов

## Зависимости:

- сервер
  - база данных postgresql
- агент
  - для локального хранения используется sqlLite что требует лишь наличие прав на создание или редактирование файла бд который вы указываете в конфиге

## Запуск

Для корректной работы приложения нам понадобится рабочий сервер и собранный исполняемый файл:

- Запуск сервера:
  - перед первым запуском изучите файл настроек configs/server.config.json где как минимум нужно задать корректные настройки связи с базой данных DatabaseDsn и ключ шифрования Security.Key
  - далее используя команду ```make run_server``` можно запустить сервер  (вы так же можете скомпилировать исполняемый файл под интересующую вас систему например командой ```make build_server_linux_64``` и выполнить его самостоятельно с полным списком доступных систем(команд) можно ознакомится в файле makefile)

- Запуск агента:
  - перед первым запуском изучите файл настроек configs/agent.config.json где как минимум нужно задать корректные ключи rsa в формате PEM Crypto.PublicKey и Crypto.PrivateKey, а так же настройки базы данных в виде пути с названием файла бд DataBase.Path файл/путь должен быть доступн на редактирование
  - далее используя команду ```make build``` можно скопилировать агент и далее его запустить (вы так же можете скомпилировать агент под интересующую вас систему например командой ```make build_win_32``` с полным списком доступных систем(команд) можно ознакомится в файле makefile)
  
## Пример работы агента

В агенте есть система помощи и при вызове любой команды достаточно добавить флаг -h чтобы прочитать инструкцию по использованию

Базовые функции:
- регистрация ```agent user sign-up -l=test -p=123456qQ ``` -l= логин -p= пароль
- авторизация ```agent user login -l=test -p=123456qQ ``` -l= логин -p= пароль
После того как прошли процесс авторизации/регистрации данные о пользователе сохраняются в сессию и можно использовать функции работы с хранилещем такие как:
- синхронизация ```agent store sync``` загрузит все секреты в локальное хранилище если есть локальные не сохраненные секреты они будут отправлены на сервер
- загрузка ```agent store load -t=binary -l="qwerty"``` -t= тип запрашиваемых данных -l= лейбл если сервер будет недоступен клиент сделает несколько попыток связаться с ним и дальше попробует достать локальную копию секрета
- сохранение ```agent store save -t=binary -l="qwerty" -d="{"json":1}"``` -t= тип запрашиваемых данных -l= лейбл -d= данные с фоматом данных и прочими флагами вы можете ознакомится через раздел помощи(флаг -h) данный метод отправляет данные на сервер если сервере недоступен он делает несколько попыток и дальше сохраняет локальную копию которую можно будет отправить на сервер повторно используя команду синхронизации
- удаление ```agent store delete -t=binary -l="qwerty"``` -t= тип запрашиваемых данных -l= лейбл удаляет выбранный label
- список ```agent store list -t=binary``` выводит список сохраненных секретов с данным типом
